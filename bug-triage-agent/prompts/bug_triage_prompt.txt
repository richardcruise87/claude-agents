## Step 10: Analyse Bug Introduction and Affected Branches

Determine which commit(s) introduced the bug and which branches are currently

### 10a. Find the introducing commit(s)

Use git commands against {devstack_path}/octavia. Try several approaches:

```bash
# Search for the string/symbol that causes the failure
git -C {devstack_path}/octavia log --all -S "problematic_symbol_or_string" --oneline | head -20

# Blame the specific line in the affected file
git -C {devstack_path}/octavia blame -L <start_line>,<end_line> -- <path/to/file.py>

# Search commit messages for related feature or fix keywords
git -C {devstack_path}/octavia log --all --grep="keyword" --oneline | head -20

# Get full details for a candidate commit
git -C {devstack_path}/octavia show <hash>

# Extract the Change-Id from a commit (used to build the Gerrit link)
git -C {devstack_path}/octavia show <hash> | grep "Change-Id:"
```

For each introducing commit collect:
- Full commit hash
- Change-Id (from the commit message `Change-Id: I...`)
- One-sentence description of how this change caused the bug

The Gerrit link is: {gerrit_base_url}/q/<Change-Id>
